# Requirement: RQ-002

## Title

The AI model an organization selects must be the model that is actually used

## Description

Administrators choose which Claude model the product should use from the
Settings screen. The choice is offered per organization, alongside the relevance
threshold, the article age window and the brand voice, and it is presented as a
cost and quality decision: a faster, cheaper model for routine scoring, a more
capable one for editorial judgement.

The choice currently has no effect. The selection is accepted, stored, and shown
back on the screen, so the interface reports that it took hold, but the work is
carried out by a fixed model that no administrator can influence. An
organization that switches to the cheapest model still pays for the most
expensive one, and one that switches to the most capable model does not get the
quality it asked for.

The record kept of each curation run makes this worse rather than visible. Each
run stores the model it says it used, and that record is written from the same
fixed value, so the history agrees with the mistake instead of exposing it.
There is no way, from inside the product, to discover that the setting is inert.

Two neighbouring settings behave inconsistently in the same way. The relevance
threshold is respected when scoring articles along one path and ignored along
two others, so identical content can be accepted or rejected depending on how
the run was started. The embedding model choice is stored and never used at all.

The goal is that every setting the product offers either takes effect or is not
offered, and that the record of each run states what was actually used.

## Source

Found during the review that followed the version 5 model update: the default
model was changed in configuration and in the database, and the change was
traced to confirm it reached the work. It did not. Raised by Julian Andrade.

## Actions

1. **Apply the selected model**: The system must carry out every AI task for an
   organization using the model that organization has selected.
2. **Apply the selection to all AI work**: The system must use the selected
   model for article scoring, article summarising, newsletter drafting, and the
   interpretation of web search requests and results, so one choice governs the
   whole product rather than part of it.
3. **Fall back predictably**: The system must use a documented default when an
   organization has expressed no preference, and must continue to work rather
   than fail when the stored preference cannot be read.
4. **Record what was used**: The system must record, for each curation run, the
   model that actually performed the work, so a run's cost and quality can be
   explained afterwards.
5. **Apply the relevance threshold consistently**: The system must apply the
   organization's relevance threshold identically however a run was started.
6. **Refuse unknown selections**: The system must not accept a model selection
   it does not offer.
7. **Report an unusable selection**: The system must tell an administrator when
   a stored selection can no longer be used, rather than silently substituting
   another model.

## Preconditions

- The organization exists and has settings of its own.
- The administrator is authorized to change the organization's settings.
- The model offered for selection is one the product supports.

## Postconditions

- Work performed for the organization uses the selected model.
- The record of each run names the model that performed it.
- An administrator can change the model and observe the change in what the next
  run reports.
- Organizations that never expressed a preference are unaffected.

## Inputs

- **Model selection**: The model an organization chooses for its AI work.
- **Default model**: The model used when no choice has been expressed.
- **Relevance threshold**: The minimum score an article must reach to be kept.
- **Run request**: A request to curate content, draft a newsletter, or search.

## Outputs

- **Scored and summarised articles**: Produced by the selected model.
- **Newsletter drafts**: Produced by the selected model.
- **Run record**: States the model that performed the run, alongside the
  thresholds that applied to it.
- **Notice of an unusable selection**: Shown to an administrator when a stored
  choice can no longer be honoured.

## Business Rules

- **BR-001**: A setting the product offers must take effect, or must not be
  offered.
- **BR-002**: A stored preference governs the work performed for the
  organization that stored it, and for no other organization.
- **BR-003**: A record of work performed must state what was actually used, not
  what was intended.
- **BR-004**: A value the product does not offer must be refused when it is
  submitted, not when it is used.
- **BR-005**: The absence of a preference must resolve to a documented default,
  never to a failure.
- **BR-006**: The same rule applied to the same content must reach the same
  outcome regardless of how the work was started.

## Dependencies

- The ability to store settings per organization.
- The ability to read an organization's settings when work is performed on its
  behalf.
- A record of curation runs that can hold what was used.
- The availability of the AI provider for the selected model.

## CRUD Operations

- **CREATE**: A run record stating the model and thresholds that applied.
- **READ**: An organization's model selection and thresholds, when work begins.
- **UPDATE**: An organization's model selection, by an authorized administrator.
- **DELETE**: None. No selection or record is removed by this requirement.
