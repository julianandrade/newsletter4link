## Risk Assessment

- **`rds_prod`.`instance_class`**: Changing the RDS instance class from `db.m5.large` to `db.t3.medium` requires a stop-and-start of the database instance. AWS performs this during the maintenance window or immediately if "apply immediately" is set. Estimated downtime: 2–5 minutes. The new instance is a burstable class — sustained CPU workloads will consume burst credits and may be throttled. Run `terraform plan` before applying to confirm the replacement.
- **`nat_gateway_prod_b` removal**: Removing the second NAT gateway eliminates high-availability outbound routing for the prod VPC. If the remaining NAT gateway's availability zone (eu-west-1a) experiences an outage, all outbound internet traffic from private subnets in eu-west-1b will fail. This is a permanent HA reduction until a second gateway is restored. The gateway itself will be destroyed by Terraform on apply.

## Constraints and Warnings

- **RDS instance class family change**: Downgrading from `db.m5.large` (memory-optimised, 8 GB RAM) to `db.t3.medium` (burstable, 4 GB RAM) reduces both CPU capacity and memory. Confirm that the production query workload and active connection count are compatible with the lower spec before applying. A staging rehearsal is recommended.
- **ASG desired_capacity reduction**: `desired_capacity` is changing from 2 to 1. This reduces the number of running EC2 instances to one, removing compute-layer redundancy. The load balancer will still be active, but a single instance failure will cause application downtime until ASG launches a replacement (typically 2–3 minutes).
